# API Error Code Reference

Complete reference for all HTTP error codes returned by the Ethos-Protocol API, client-side errors generated by the mobile apps, and recovery steps for each.

## HTTP Error Codes

### 400 Bad Request

The request was malformed or failed server-side validation.

| Scenario | Response Body | Recovery |
|----------|--------------|----------|
| Replay detected (duplicate nonce) | `{"error": "replay_detected"}` | Generate a fresh `X-Nonce` and current `X-Timestamp`, then retry the request |
| Replay detected (stale timestamp) | `{"error": "replay_detected"}` | Ensure device clock is correct; retry with a fresh nonce and current timestamp |
| Invalid request body | `{"error": "<message>"}` | Fix the request payload; see [shared/api-contract.md](../shared/api-contract.md) for field requirements |

**Client behavior:** iOS throws `APIError.serverError(message)`; Android returns `ApiResult.Error(message, 400)`.

### 401 Unauthorized

The request lacks a valid authentication token.

| Scenario | Response Body | Recovery |
|----------|--------------|----------|
| Missing or expired JWT | *(empty)* | Sign in again — the client deletes the stored token automatically |
| Invalid JWT | *(empty)* | Sign in again |
| Expired recovery token | `{"error": "Your recovery code has expired. Please request a new one."}` | Request a new recovery code; surface the message as-is |
| Invalid acceptance token | `{"error": "<message>"}` | The acceptance link is expired or already used; ask the owner for a new link |

**Client behavior:** iOS throws `APIError.unauthorized` (or `APIError.serverError(message)` when a body message is present); Android clears the token and returns `ApiResult.Error(message, 401)`.

### 404 Not Found

The requested resource does not exist or does not belong to the caller.

| Scenario | Response Body | Recovery |
|----------|--------------|----------|
| Vault not found | `{"error": "Not found"}` | Verify the vault ID; the vault may have been deleted |
| Session not found | `{"error": "<message>"}` | The session may have already been revoked |

**Client behavior:** iOS throws `APIError.notFound`; Android returns `ApiResult.Error("Not found", 404)`.

### 409 Conflict

The request conflicts with the current state of the resource. Used as an alternative to 400 for replay detection.

| Scenario | Response Body | Recovery |
|----------|--------------|----------|
| Replay detected | `{"error": "replay_detected"}` | Same as 400 — generate a fresh nonce and timestamp |

### 410 Gone

The vault has already expired and the check-in is no longer valid.

| Scenario | Response Body | Recovery |
|----------|--------------|----------|
| Vault expired | *(varies)* | The vault has expired; no action needed. The client deletes the queued check-in and shows a notification |

**Client behavior:** `CheckInSyncTask` (iOS) and `PendingActionSyncWorker` (Android) treat 410 as a non-retryable error, delete the queued item, and post a local notification.

### 429 Too Many Requests

The request was rate-limited.

| Scenario | Response Body | Recovery |
|----------|--------------|----------|
| Rate limited | *(varies)* | Respect the `Retry-After` response header; wait the indicated seconds before retrying |

**Client behavior:** Android reads the `Retry-After` header and returns `ApiResult.Error("Rate limited. Retry after N seconds.", 429)`. iOS does not currently handle 429 explicitly — it falls through to the generic server-error path.

### 5xx Server Error

The server encountered an unexpected condition.

| Scenario | Response Body | Recovery |
|----------|--------------|----------|
| Internal server error | `{"error": "<message>"}` or *(empty)* | Retry with backoff; if the problem persists, contact support |
| Service unavailable | `{"error": "<message>"}` | Retry with backoff |

**Client behavior:** iOS throws `APIError.serverError(message)`; Android returns `ApiResult.Error("Server error N", N)`.

## Client-Side Errors (Non-HTTP)

These errors are generated locally by the mobile apps and do not correspond to an HTTP response.

### Network Unavailable

The device has no network connectivity.

| Platform | Error Message | Recovery |
|----------|--------------|----------|
| iOS | "No internet connection" | Check network settings; the app will automatically use cached data for reads |
| Android | "No network connection" | Check network settings; the app will automatically use cached data for reads |

**Client behavior:** Thrown before any HTTP request is made. For GET requests, the app serves cached data if available. For mutations, the action is queued for retry (check-in) or the error is surfaced to the user.

### Decoding Failed

The server response could not be parsed into the expected model.

| Platform | Error Message | Recovery |
|----------|--------------|----------|
| iOS | "We couldn't read the server's response" | Try again; if the problem continues, contact support — this has been logged |
| Android | "Something went wrong. Please try again." | Try again; if the problem continues, contact support |

**Client behavior:** iOS throws `APIError.decodingFailed`; Android's `ApiErrorMapper` catches the exception and returns a generic error. The failure is logged via `DecodingFailureLogger` (iOS).

### Circuit Breaker (Android only)

The Android client's circuit breaker has opened due to consecutive failures.

| Platform | Error Message | Recovery |
|----------|--------------|----------|
| Android | "API temporarily unavailable" | Wait for the circuit breaker to half-open, then retry |

**Client behavior:** Returned as `ApiResult.Error("API temporarily unavailable", 503)` when `circuitBreaker.allowRequest()` returns false.

### OTP Rate Limiter (Client-Side)

The client-side OTP verification rate limiter has engaged after repeated failures.

| Platform | Error Message | Recovery |
|----------|--------------|----------|
| iOS | "Too many attempts — wait Ns" | Wait for the cooldown to expire; the countdown is displayed in the UI |
| Android | "Too many attempts — wait Ns" | Wait for the cooldown to expire; the countdown is displayed in the UI |

**Cooldown schedule** (both platforms):

| Cumulative Failures | Cooldown |
|---------------------|----------|
| 1–2 | None (grace period) |
| 3 | 30 seconds |
| 4 | 60 seconds |
| 5+ | 120 seconds (capped) |

A successful verification resets all counters. State persists across app restarts.

### Username Validation (Client-Side)

The username entered during passkey registration does not meet the policy.

| Validation Rule | Error Message |
|----------------|--------------|
| Too short (< 3 chars) | "Username must be at least 3 characters." |
| Too long (> 30 chars) | "Username must be 30 characters or fewer." |
| Invalid characters | "Username can only contain letters, numbers, underscores, and hyphens." |

### Passkey/CredentialManager Errors (Client-Side)

Errors from the platform WebAuthn/Passkey APIs.

| Platform | Error | Recovery |
|----------|-------|----------|
| iOS | `ASAuthorizationError.canceled` | User cancelled the biometric prompt; no action needed |
| iOS | `ASAuthorizationError.notInteractive` | Retry the operation |
| Android | `CreateCredentialCancellationException` | User cancelled; no action needed |
| Android | `CreateCredentialNoCreateOptionException` | No passkey provider available; check device settings |
| Android | `NoCredentialException` | No matching credential found; sign in with a different method |

## Error Code Lookup

Use the lookup tool to find error codes by number or keyword:

```bash
python3 scripts/lookup_error_code.py <code-or-keyword>
```

Examples:

```bash
python3 scripts/lookup_error_code.py 401
python3 scripts/lookup_error_code.py replay
python3 scripts/lookup_error_code.py rate
```
